# GaragePulse Web

Web client for GaragePulse, a multi-tenant garage/workshop CRM. Job cards,
estimations, invoicing, inventory, customers, vehicles, staff, dashboards, plus
a platform-admin console and a public estimation-approval page.

**Stack:** React 19 · Vite · TypeScript (strict) · Tailwind CSS 4 ·
React Router 7 · Axios · Recharts · lucide-react · Vitest + React Testing Library

Companion repositories: [`garageCrm-be`](https://github.com/Dins2344/garageCrm-be)
(API) and [`garageCrm-app`](https://github.com/Dins2344/garageCrm-app) (mobile).
All three deploy independently.

---

## Prerequisites

- **Node 20** and **npm 10** — pinned in `.nvmrc` and `engines`. A lock file
  generated by a newer npm will fail CI's `npm ci`, so run `nvm use` first.
- A running **GaragePulse API** (see `garageCrm-be`), or a deployed one to
  point at.

## Getting started

```bash
nvm use                                        # Node 20
npm ci                                         # exact dependency install
echo "VITE_API_URL=http://localhost:5000/api" > .env
npm run dev                                    # http://localhost:5173
```

## Environment variables

Vite only exposes variables prefixed `VITE_`. `.env*` files are gitignored.

| Variable | Required | Notes |
| --- | --- | --- |
| `VITE_API_URL` | no | API base URL. Defaults to `http://localhost:5000/api` when unset — set it explicitly for any deployed build |

## Testing

Vitest + React Testing Library, with API service modules mocked — tests never
hit the network. Tests are **colocated** with the file they cover
(`Customers.tsx` → `Customers.test.tsx`).

```bash
npm test
```

Two things to know when writing tests:

- Query by **role or label**, not by placeholder text. Placeholders follow the
  garage's country now, so `getByPlaceholderText('9876543210')` breaks for a
  non-Indian tenant.
- Any page calling `useGarage()` needs `GarageContext` mocked with a real
  `locale`. The provider never yields `undefined`, so a mock that does is
  testing an unreachable state.

## Known lint state

`npm run lint` currently reports **6 pre-existing errors** — three
`react-hooks/set-state-in-effect` (a new rule in eslint-plugin-react-hooks v7,
firing on code that predates it) and three `react-refresh/only-export-components`
on the context files. CI runs typecheck, tests and build but **not** lint, which
is why they have persisted. Don't add to them.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds a
Docker image serving the static build through Nginx, pushes it to Docker Hub
and redeploys, finishing with a health check. It can also be run manually
(`workflow_dispatch`).

Before pushing a dependency change, confirm the lock file still satisfies CI's
npm:

```bash
npx -y npm@10 ci --dry-run
```
